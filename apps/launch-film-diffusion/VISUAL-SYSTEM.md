# Visual system — real asset pass

The active pass uses authored motion plus a small set of real, local brand marks. Every asset remains readable at social-feed scale; no remote asset is loaded during render.

| Family | Purpose | Variants and motion |
| --- | --- | --- |
| Terminal shell | Establishes a believable local CLI surface. | Perspective entrance, character-by-character transcript, per-character pop/settle, deterministic cursor, camera push-in, and tool escape paths. |
| Brand mark | Makes a capability recognizable rather than invented. | Cached local SVG paths for the selected tools and the final ecosystem orbit; warm native folder glyph for Filesystem; supplied multicolour Roster mark; monochrome-on-dark or native-colour-on-light treatment. |
| Tool object | Gives each capability a physical, readable container. | Candidate and hero sizes only; shell settles first, then mark, title, and one capability line, with a restrained arrival overshoot. |
| Fit shortlist rail | Makes task-based selection legible without a dashboard wall. | Five real-mark candidates, one neutral glass beam, a single `RIGHT FIT` focus state, and a final `5 OF 200 / READY` lock. The five decorative under-card rails are intentionally omitted; only the main scan rail remains. |
| Connection route | Makes spatial relationships legible outside the execution beat. | Terminal traversals use a slim, glassy path with a quiet neutral edge and one restrained signal colour per route (coral, mint, or sky). Reduced halo and no fluffy glow keep the curves crisp at social scale. They never carry the hero execution scene; the call beat uses physical object transfer instead of a connector diagram. |
| Roster aperture | Turns task routing into a decisive product action. | A Claude Code request is absorbed by a dark optical selector; five real marks sweep through a clipped glass viewport, GitHub locks into focus, and a success receipt is physically ejected. The aperture uses a single staged choreography—intake, resolve, lock, output—with no persistent paths or decorative traffic. |
| Roster mark | Supplies one coherent product object. | The current user-supplied `roster-logo.png` is the active source of truth in every Roster placement. It is rendered at its native 395×512 transparent aspect ratio, displayed in black for the paper scenes, and given a white rounded plate only inside the central routing core. Earlier `roster.png` and `roster-clean.png` files remain preserved for rollback. |
| Final identity orbit | Shows ecosystem breadth without a logo collage. | Seventeen real local marks from agent-facing integrations share one elliptical track, enter already coasting at readable speed, decelerate into a balanced halo, and give only five marks a subtle partial glass arc. Miro uses its official full-colour icon; small inward tethers provide a visual relationship to Roster without a spiderweb of routes or boxed UI chips; runtime/model marks are intentionally excluded. |
| Brand lockup | Converts the selection into a usable launch card. | Five neutral glass traversals, wordmark, launch line, command, and local-first claim. |

Rules: one focal point per frame; no card collision at sampled frames; critical type is at least 24 px at 1920×1080; important strokes are at least 2 px; no ambient particles, random sprites, or persistent HUD chrome. The authored system stays cool graphite/paper/glass/sage; native tool colours remain visible only on sourced marks, with copper route packets used sparingly as motion signal. Avenir Next is the preferred display family, with system fallbacks in `src/real/design.js`. `src/real/brandPaths.js` is generated from the SVGs in `assets/brands/` and must be regenerated with `node scripts/make-brand-paths.mjs` after an asset update.
