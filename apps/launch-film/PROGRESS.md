## How to resume

```sh
cd apps/launch-film
pnpm install                     # from the repo root, once
pnpm fonts                       # copy OFL fonts into public/fonts
pnpm audio                       # regenerate the score from src/audio/cues.ts
pnpm studio                      # http://localhost:3000
pnpm typecheck
pnpm stills                      # 33 QA frames into out/stills
pnpm contact-sheet               # rebuilds public/qa + the contact sheet
pnpm preview && pnpm master && pnpm poster
pnpm probe                       # technical verification of the master
```

Everything timing-related lives in `src/motion/timing.ts`. Everything the film
*says* lives in `src/productCopy.ts`. Those two files are the edit surface for
90% of changes.

## Environment notes (found the hard way)

- **`ffmpeg` is not installed** and the Playwright-bundled build at
  `/opt/pw-browsers/ffmpeg-1011/ffmpeg-linux` is compiled with `--disable-everything`
  (VP8/WebM/PNG only, no H.264, no AAC). Remotion's own Rust compositor handles
  the H.264 + AAC encode, and `scripts/probe-master.mjs` uses
  `@remotion/media-parser` for verification instead of `ffprobe`. **Do not add an
  ffmpeg dependency to this app.**
- Remotion's webpack bundler does **not** resolve `./x.js` → `./x.tsx`. All
  relative imports in `src/` are extensionless. (Node's own TS loader wants the
  opposite, which is why `scripts/*.mjs` run under `tsx`.)
- 4 CPUs available; renders run at **concurrency 3** (`remotion.config.ts`).
  Four tabs on four cores starved the style/font pass; three is reliable.
  Measured on this machine: 0.5× preview 338 s, 1080p master 1152 s, teaser 240 s.
- **Fonts must not be loaded through a promise.** `@remotion/fonts`
  `loadFont()` intermittently never settled under concurrent rendering and the
  `delayRender()` timed out at 118 s — with an HTTP url *and* a data url. A
  `document.fonts.ready` race with a `setTimeout` escape hatch also deadlocked,
  because Remotion replaces the page's timers with a deterministic clock, so the
  timeout never fires. `src/design/typography.ts` now installs plain
  `@font-face` rules with `data:` sources and waits on nothing.
- The `Detected differing memory amounts` warning from Remotion is a container
  cgroup artefact and is harmless.

## Open items / honest limitations

- **No prior film existed in this worktree.** `git status` was clean at the start
  and `apps/launch-film` did not exist, so there is no earlier master to diff
  against and no earlier render to preserve as a "before". The before/after sheet
  therefore compares against a *rendered reconstruction* of the rejected dark-HUD
  direction (`src/qa/RejectedDirection.tsx`), clearly labelled as such on the
  sheet itself.
- **Figma MCP is not connected in this session.** All styleframes and components
  are code-native. Nothing in the film depends on Figma.
- The Day-0 receipt numbers in the terminal beat are *illustrative* of one
  machine's run and the frame says so on screen. They are the real output shape
  of `packages/cli/src/receipt.ts`, not a recording of a specific user's run.
- The score is synthesised, not composed by a musician. It is deliberately
  restrained; the film is designed to work muted.
- **The README gif cannot use `remotion render --codec=gif`** while
  `remotion.config.ts` sets a global CRF for the master — the CLI rejects `--crf`
  on the gif codec. `pnpm gif` therefore goes through `scripts/render-gif.mjs`
  and `renderMedia()`, which lets that one output opt out of the film's encode
  settings without weakening them for the master.
- **Repository dependencies were not installed in this container** when the work
  started (`pnpm install` had never been run for the workspace), so the first
  `pnpm typecheck` failed on missing `better-sqlite3`, `yaml` and
  `@modelcontextprotocol/sdk`. That was environment state, not a regression: a
  full `pnpm install` fixed it and all four repository checks then passed.
- `apps/launch-film` is deliberately **not** added to the root `tsconfig.json`
  project references or to `pnpm build`. It is a React/JSX app with different
  compiler settings, and wiring it into the library build would have changed the
  repository's existing gates.
- **Root-manifest state, disclosed in full.** `git status` at the end shows four
  tracked files changed:
  · `pnpm-lock.yaml` and `pnpm-workspace.yaml` — the unavoidable result of adding
    a workspace package. pnpm 11 wrote the `minimumReleaseAgeExclude` block in
    the workspace file itself so the freshly-published Remotion 4.0.502 packages
    resolve; without it `pnpm install` refuses them.
  · `biome.json` — the narrow override described below.
  · Root `package.json` was briefly modified by a script that ran from the wrong
    working directory, and was **reverted with `git checkout --`**. It is clean.
  Nothing else in the repository was touched, and nothing was committed or pushed.
- **One shared-config change was made:** `biome.json` gained an `overrides` entry
  disabling `correctness/useUniqueElementIds` for `apps/launch-film/src/Root.tsx`
  ONLY. Remotion's `<Composition id="…">` / `<Still id="…">` take a composition
  *name*, not a DOM id, and the prop cannot be renamed. Every other violation of
  that rule was fixed in code (SVG `<defs>` ids now come from `defId()`, and the
  `Connection` component's id-seed prop was renamed to `trace`). Nothing else in
  the repository's lint configuration was touched, and `pnpm lint` passes.
